# 議事録作成（Discussion Record）

長い議論スレッドを、後から参照できる記録用ドキュメントに変換する。要約ではなく、
ユーザーの発言を原文で保存し、Claude の応答を要点に圧縮した「対話ベースの記録」を作る。
さらに、各発言の直下にその発言の要点を箇条書きサマリーとして添え、読み手がサマリーだけを
追えば論旨を速やかにつかめ、詳しく見たいときは上の本文に戻れる二層構造にする。

**このスキルの核心**: 過剰な形式化はこの成果物を再現できなくする。だから細かいテンプレートに
従うのではなく、下記の6原則を守りつつ、必ず `references/sample_discussion.md`（ゴールド
サンプル）を読んで、その構成・圧縮度・見た目に倣うこと。サンプルが仕様であり、この本文は
その読み方の指針にすぎない。

## 手順

1. **まず `references/sample_discussion.md` を読む。** これが目標とする成果物の完成形。
   見出しの粒度、ユーザー発言の原文の残しかた、各発言の下のサマリーの粒度、Claude 側の
   圧縮度、全体の見た目を体感する。以降の判断に迷ったら、散文の規則ではなくこのサンプルに
   合わせる。

2. **論点で区切る。** スレッドの実際の流れに沿って、議論を論点ごとの見出しに分ける。
   細かすぎると読みにくく、粗すぎると発言の起点が埋もれる。サンプルと同程度の粒度を狙う。
   最初に見出しの一覧を作り、ユーザーに見せて確認を取ってから本文に進むとよい。

3. **各論点は「ユーザー発言（原文）→ そのサマリー → Claude の要点 → そのサマリー」の順で
   書く。** これが基本単位。ユーザー発言の下には「オーナーの論点」等のラベルで要点を箇条書きし、
   Claude 応答の下には「Claudeの回答要点」として要点を箇条書きする。各サマリーは概ね1〜5行。

4. **完成後、冒頭に短い前書き、末尾に「到達点」を置く。** サンプルの冒頭・末尾に倣う。
   冒頭の前書きには、この文書が二層構造（原文・要点＋サマリー）であること、正本が別にあるなら
   その参照を1〜2文で書く。末尾の「到達点」は議論全体の結論を数文でまとめる（ここには
   サマリー箇条書きは付けない）。

## 6つの原則（これだけは必ず守る）

1. **ユーザーの発言は原文のまま、一字も直さず入れる。** 一つの論点でユーザーが複数回
   発言していれば、その全てを原文で入れる。省略・要約・代表発言だけの抜粋はしない。
   誤字や口語もそのまま。**発言を創作・補完しない**——実際に無い発言を括弧書きで補うのは
   禁止。原文が手元にあるものだけを使う。

2. **各発言の直下に、その発言の要点を箇条書きサマリーで添える。** これがこの記録の二層構造の
   核心。ユーザー発言の下は「オーナーの論点」等のラベル、Claude 応答の下は「Claudeの回答要点」の
   ラベルで、概ね1〜5行の箇条書きにする。サマリーは上の本文の主張を要約するもので、本文に無い
   内容を足さない。本文（原文・要点）は残したまま、その要約を下に付ける形であって、本文を
   サマリーで置き換えるのではない。

3. **Claude の応答は対話の再現ではなく、要点に圧縮する。** 「その通りだ」「説明する」等の
   相槌・導入・言い換え・丁寧な繰り返しは削る。確定した結論と、その根拠の芯だけを残す。
   見出しと箇条書きで論旨が速やかに追える形にする。

4. **決定/理由/却下の固定テーブルにはしない。** 構造化された決定記録（decisions 表など）は
   別文書の仕事。この議事録はあくまでユーザー発言を起点に、そこへの応答の要点が続く
   対話ベースの見た目を保つ。

5. **論点の区切りはスレッドの実際の流れに従う。** 理想的な分類体系を後付けするのではなく、
   議論が実際にどう進んだかの切れ目で区切る。

6. **「なぜその結論に至ったか」を残す。** これは最終的な決定リストではなく、思考の経緯の
   記録。確定事項の正本が別にあるなら（decisions文書や仕様書など）、末尾でそれを参照し、
   この文書は経緯を残すためのものだと明記する。

## 配置とファイル名

- 記録用ドキュメントとして、構造化された決定文書とは別に置く（例: `docs/` 直下）。
- ファイル名はユーザーの既存の命名慣習に合わせる（サンプルは `discussion<年><主題>.md` の形）。
- ユーザーに配置場所とファイル名を確認する。

## 注意

- スレッドが長い場合、ユーザー発言の原文をすべて拾うため、本文を前半・後半に分けて
  書いてよい。ただし最終的に1ファイルにまとめる。
- 見出しの粒度は後から統廃合できる。まず一覧を提示し、ユーザーの粒度の好みを掴んでから
  全体を通すと、トーンが一発で揃う。
- Claude 側の圧縮度は論点ごとに調整可能。「この論点はもう少し残したい／もっと削りたい」
  というユーザーの要望に応じる。
