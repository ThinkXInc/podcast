## 1. 選択肢の洗い出し — EC2 / ローカルMac公開 / zip配布

> **このシステムを他の人も使えるようにするにはどうするのが簡便かつ安上がりな方法だろう**
> **EC2でサーバーを動かしている　EC2は2台の小さいサーバーで月5000円ほどかかる**
> **ロードバランサーとwebサーバーのセットがあり完成された仕組みなのでEC2ならこれを使う以外に考えにくい**
> **私のローカルmacをpublic ipでホストする方法はあるのだろうか**
> **私のmacがネットに繋がっていないと作業者は作業できないなどの制約はあるかもしれないが**
> **サーバーのスペックは編集操作に支障なければいい**
> **自宅に固定IPとサーバーをもっていたがもう回線を解約したので固定IPは使えない**
> **buffaloのルーターにipを固定する方法があれば自宅のネットワークからホストできるかもしれない**
> **このシステムを別のサーバーにデプロイなどすると私の作業が増えてペイしないだろう**
> **何かいい方法はないか**
> **このシステムを作業者のシステムにインストールするのはありかもしれないがwindowsを使っている場合が多い**
> **ソースをzipで渡して解凍してサーバーを起動するコマンドを手順書に渡す　ファイルも一緒に同梱する　ということ**
> **他にいい案は思いつかない**

**オーナーの論点**
- 簡便・安上がりが条件。既存EC2（2台＋LB・月5,000円）は完成された仕組みなので使うならこれ
- ローカルMacの公開も検討したいが、固定IPは回線解約で失った。Buffaloルーターでの固定は可能性として
- 別サーバーへのデプロイは自分の作業が増えてペイしない
- 作業者は Windows が多い。zip＋手順書＋同梱ファイルの配布案はあるが、他にいい案はないか

3案を比較し、**案1: 既存EC2に載せる**を推奨。理由は (a) 追加費用ゼロ、(b) 作業者は
ブラウザだけ・Windows でも何も入れない、(c) 編集はサーバー上のJSONに直接保存されるので
**返送作業も不要**、(d) `web/` はもともとこの形を想定した設計（`nginx/conf.d/podcast_web.conf`
に uWSGI socket・`/media/` 直接配信・ポート8010が用意済み）で「完成された仕組みに載せるだけ」。
オーナーの手間はエピソードごとの同期コマンド1発（publish/collect スクリプトを作る前提）。

- 案2（Mac公開）: Buffaloのポート開放＋DDNSは非推奨——国内回線は IPv6（MAP-E/CGNAT）で
  ポート開放できないことが多く、できても生HTTPで自宅網を晒す。やるなら Cloudflare Tunnel か
  Tailscale（無料・固定IP不要・認証付き）だが、**Macが起動して繋がっている間しか作業できない**
- 案3（zip配布）: サイト本体は依存ゼロなので Python embeddable 同梱＋bat で作れるが、
  編集結果の zip 返送・バージョン配り直し・「動かない」対応がオーナー持ちで、人数に比例して
  運用負債になる。オフライン作業が要る場合だけの選択肢
- 運用上の注意: 同一IDの同時編集は後勝ち上書きなので「1エピソード=1担当」で回す

## 2. 案1の具体化 — thinkx-system モノレポへの移管

> **もし案1をやるならthinkx-systemモノレポにこのpodcastレポジトリを入れることになるだろう　それはありだと思う　thinkx-systemにはデプロイの仕組みが完全にある setup_podcast.sh でサイトのセットアップを一つ追加すればいいはず uwsgiアプリケーションを起動すればproductionサーバーが常に動いてネットにも繋がっている ClaudeCodeプロセスはproductionには置いていない　必要なら追加してもいい stagingはよく停止するのでproductionだろう**

**オーナーの論点**
- 案1なら podcast リポジトリを thinkx-system モノレポに入れる。それはあり
- thinkx-system にはデプロイの仕組みが完全にあり、setup_podcast.sh を1つ足せば済むはず
- uWSGI アプリとして production サーバーに常駐させる（staging はよく停止する）
- Claude Code プロセスは production に無いが、必要なら追加してもいい

方針に同意し、ギャップは3つだけと整理。
1. **WSGIアダプタ**（唯一のコード作業）: `preview_local.py` は標準ライブラリのHTTPサーバー
   直書きで WSGI モジュールではない。`web/wsgi.py` の薄いアダプタを書けば uWSGI に載る
2. **データ往復スクリプト**: production は編集専用（AI・ffmpeg工程は置かない）。
   `publish.sh <ID>`（preview_audio.m4a・transcript.json・edit/ 等の最小セットをrsync。
   元WAV 242MBは送らない）と `collect.sh <ID>`（edit/*.json 回収）。書き出しボタンは
   サーバーでは非表示にし、回収後ローカルで書き出す
3. **認証**: 現状認証ゼロなので nginx の Basic 認証を必須で足す

Claude Code の production 常駐は当面不要（編集はブラウザで完結、AI工程は全部ローカル側）。

## 到達点
