切り抜き（SNS用ショートクリップ）候補の抽出プロンプト。

対象は**編集済みのフル音源**（会話相手カット・無音詰めなど本編の編集が終わったもの）の
文字起こしである。実行者は Claude（D-024。GPT APIは使わない）。
本編の候補抽出（prompt_all.txt）とは目的も基準も逆なので混同しないこと。

## 目的

切り抜きは**アクセスを稼ぐフック**である。SNS（X / Instagram Reels / YouTube Shorts / TikTok）で
流れてきた人の手を止め、「続きを聴きたい」と思わせて Podcast 本編へ遷移させるのが唯一の目的。
本編のような「議論を通しで味わう」完成度は要らない。

## 選定基準（prompt_all.txt と逆になっている点に注意）

1. **尺は 10〜30秒**。本編の「長尺優先」は適用しない。
   1クリップ＝1パンチライン。導入・経緯・補足は全部本編に譲り、
   話の核（強い断言・種明かし・オチ）だけを残す。文脈の不足はSNSキャプションで補う。
   長い話は途中を drops で詰めてでも30秒以内にする。30秒に収まらない話は候補にしない。
   （2026-08-24 オーナー指示により 30秒〜3分 → 20〜60秒 → **10〜30秒** と改定。これが最終）
2. **冒頭3秒で掴めること**が最重要。切り出しの頭が
   「強い断言・意外な言葉・問い・比喩」のどれかで始まる位置を選ぶ。
   前置き・相槌・「で、」「まあ」等の接続から始まる切り方はしない
   （数秒後ろにずらせば強い文頭で始まるなら、そちらを開始点にする）。
3. **単体で意味が通ること**。前後の文脈を知らない人が聞いても
   「何の話か」が10秒以内にわかる区間だけを候補にする。
4. **出口は本編への引きになること**。話が完全に閉じて満足してしまう切り方より、
   主張の核を見せつつ「この先の展開・理由・実例は本編で」となる切り方を優先する。
   ただし尻切れトンボ（文の途中で終わる）は不可。文末で終える。
5. **本数に上限を設けない。10〜30秒で成立するパンチラインは全部拾う**（rank はフック力の強い順）。
   フル音源を頭から尻まで走査し、強い断言・種明かし・名言・逸話の核をすべて候補化する。
   同じ話題から複数の切り方を出してもよい。落としたものは dropped に理由付きで残す。
   （2026-08-24 オーナー指示「少なくないか？数を制限していない？」により 5〜8本の上限を撤廃）
6. 公開前チェックは本編と同じ基準を維持: 政治的断定・実在人物の名指し批判・民族・
   陰謀論・事実誤認・差別的表現が区間に含まれる場合は cuts / fact_checks に必ず出す。
   切り抜きは拡散が目的なので、本編より炎上リスクに厳しく見ること。

## 出力（自動処理用・厳守）

人間が読むMarkdown本文（要約表＋各候補のコメント）の最後に、機械可読JSONブロックを
```json で1つだけ出力する。スキーマは prompt_all.txt と互換（candidates / fact_checks）で、
切り抜き用に次のフィールドを追加する:

{
  "candidates": [
    {
      "rank": 1,
      "title": "本命タイトル（動画の見出し。短く強いフレーズ）",
      "title_candidates": ["タイトル案2", "タイトル案3"],
      "start_sec": 123,
      "end_sec": 210,
      "duration_label": "[1分27秒]",
      "hook": "なぜ手が止まるか（冒頭3秒に何があるか）を1〜2文で",
      "opening_quote": "切り出しの最初の一文（文字起こしに実在する連続した文字列を正確に）",
      "closing_quote": "切り出しの最後の一文（同上）",
      "highlight_quotes": ["区間内の象徴的なセリフを2〜4個（30〜80字・原文まま）"],
      "sns_caption": "投稿キャプション案（1〜2文＋「続きは本編で」系の導線。ハッシュタグは付けない）",
      "summary": "区間の内容要約（2〜3文）",
      "review": "選定理由・フックの根拠・懸念（あれば）",
      "cuts": [],
      "recommend": "推奨度コメント"
    }
  ],
  "fact_checks": []
}

- タイムスタンプはすべて秒（整数）。**編集済み音源の時刻**であること
  （generated/transcript.json は編集済み音源から取り直したものを使う）。
- opening_quote / closing_quote は境界調整の目印に使うので、文字起こしに実在する
  連続した文字列を正確に写す（要約・改変しない）。
- full_text は入れない（切り抜きは短いので highlight_quotes と summary で足りる。
  全文はタイムラインUIで見る）。
- exclude_zones は出さない（編集済み音源が対象なので候補外抽出は不要）。

## チャット提示（実行者向けメモ）

候補はチャットに全件出す。本数が多いので1候補はコンパクトに:
「番号・タイトル｜開始〜終了（尺）／頭『…』→尻『…』／キャプション案／⚠注意があれば」。
hook・summary・review の全文は candidates_claude.json 側に残す。
cuts / fact_checks があれば全件、1件ずつ承認を取る（勝手に確定しない）。
そのうえで candidates_claude.json（generated/）に保存し、オーナーの取捨選択を経て
edit/segments.json に流し込み、タイムラインUIで境界調整→書き出しする。
